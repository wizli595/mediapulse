# MediaPulse

Big Data platform that collects news articles from Moroccan and international press, stores/transforms/analyzes them to identify media trends.

## Project Context

School project: "Architecture de donnees". The platform must handle ingestion, storage, transformation, data quality, governance, and visualization using a distributed architecture deployed via Docker.

## Implementation Phases

See `PHASES.md` for the full implementation roadmap with checkboxes per file. This file is gitignored (internal tracking only). We build in order: Foundation -> Scraping -> Ingestion -> Storage -> Processing (Bronze -> Silver -> Gold) -> Quality -> Warehouse -> Orchestration -> Visualization -> Governance -> Deployment -> Monitoring -> Docs.

## Target News Sources

- Moroccan: Hespress, Akhbarona, Lakom, Barlamane
- International: Al Jazeera, CNN, BBC News, Reuters

## Tech Stack

| Layer           | Technology                  |
|-----------------|-----------------------------|
| Scraping        | Python + Scrapy             |

| Orchestration   | Apache Airflow              |
| Data Warehouse  | PostgreSQL                  |

| Data Quality    | Custom Python checks        |
| Governance      | Custom metadata catalog     |
| Deployment      | Docker + docker-compose     |
| Monitoring      | Prometheus + Grafana (opt.) |

## Architecture: Medallion (Bronze / Silver / Gold)

- **Bronze**: raw scraped articles stored as-is in MinIO
- **Silver**: cleaned (strip HTML, normalize text, detect language, deduplicate)
- **Gold**: aggregated analytical tables (trends, top topics, articles per source)

## Clean Code Rules

### 1. Single Responsibility (SRP)

Every function does ONE thing. Every class has ONE reason to change.

- A spider ONLY parses HTML. It does not save, publish, or validate.
- A publisher ONLY sends to Kafka. It does not scrape or transform.
- A quality check ONLY validates one rule. It does not fix data.
- A DAG ONLY defines schedule and calls layer functions. It contains ZERO business logic.

### 2. Depend on Abstractions (DIP)

Every layer defines an abstract base class. Implementations are swappable.

- `AbstractSpider` -> `HespressSpider`, `CNNSpider`
- `AbstractPublisher` -> `KafkaPublisher`, `FilePublisher`
- `AbstractStorage` -> `MinIOStorage`, `LocalStorage`
- `AbstractCheck` -> `TitlePresentCheck`, `DatePresentCheck`
- `AbstractRepository` -> `ArticleRepository`, `TrendRepository`

### 3. Open/Closed (OCP)

Adding a new news source = add one spider file. Change nothing else.
Adding a new quality check = add one check file. Change nothing else.
Registries discover implementations automatically.

### 4. No Hardcoded Values

All configuration lives in `.env` and `shared/config.py`. No magic strings in business logic.

### 5. DRY

- One `Article` dataclass in `shared/models/article.py` — every layer uses it.
- One config loader in `shared/config.py` — every layer reads from it.
- Shared exceptions in `shared/exceptions/`.

### 6. No Function Does Two Things

If you write a function that scrapes AND saves, split it.
If you write a function that cleans AND validates, split it.
Each function: ONE input -> ONE output -> ONE job.

### 7. DAGs Are Thin

Airflow DAGs only orchestrate. They call functions from the correct layer. They never contain transformation logic, SQL queries, or data manipulation.

### 8. Layers Never Skip

```
scrapers -> ingestion -> storage -> processing -> warehouse -> visualization
```

Each layer depends ONLY on `shared/` and the layer directly before it. No skipping layers. No circular dependencies.

### 9. No AI Footprint in Commits

Never add Co-Authored-By, "generated by AI", or any mention of Claude/AI in commit messages, code comments, or anywhere in the codebase. Commits must look fully human-authored.

## Data Collected Per Article

- title (str, required)
- author (str, optional)
- published_at (datetime, required)
- category (str, optional)
- content (str, required)
- source (str, required) — e.g. "hespress", "cnn"
- url (str, required)
- language (str, optional — detected in silver layer)
- scraped_at (datetime, auto-set)

## Ingestion Modes

- **Batch**: Scrapy spiders scheduled every hour via Airflow
- **Streaming**: new articles pushed as Kafka events in real time

## Data Quality Checks

Each check is one class implementing `AbstractCheck`:
- Title present (not empty)
- Date present (not null)
- Content length (not too short)
- URL valid
- Dimensions: completeness, consistency, validity
